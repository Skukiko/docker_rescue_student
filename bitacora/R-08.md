# R-08 — Los datos de PostgreSQL se pierden al recrear los contenedores

## Incidencia
Los registros guardados desaparecen después de `docker compose down` + `docker compose up -d`.

## Síntoma
```
$ curl -sS http://localhost:8080/api/items   (antes)
[{"id":1,"name":"prueba R-07","created_at":"2026-11-18T15:27:52.374886"}]
$ docker compose down
$ docker compose up -d
$ curl -sS http://localhost:8080/api/items   (después de down + up)
[]
```

## Evidencia
Archivo: `evidencias/R-08_diagnostico.txt`
```
$ docker inspect --format '{{json .Mounts}}' docker_rescue_student-db-1      (antes)
[{"Type":"volume","Name":"f046c452069eef6b...","Destination":"/var/lib/postgresql/data",...}]
$ docker inspect --format '{{json .Mounts}}' docker_rescue_student-db-1      (después)
[{"Type":"volume","Name":"bad3740c004cf0c2...","Destination":"/var/lib/postgresql/data",...}]

$ docker volume ls
DRIVER    VOLUME NAME
local     5298cea07ffef1edcb53f6709f647b292e98ae572d875c7750ac29f83784b26e
local     bad3740c004cf0c24d786c043a26cd57a4e01298fb1fb3c43ecdd21e5ac6ee9d
local     f046c452069eef6b7f80d340a5d88db213c3a1803f084f3d46ef88660e2b83c0
```

## Causa raíz
La imagen `postgres` declara `VOLUME /var/lib/postgresql/data`. Como `compose.yaml` no monta nada allí,
Docker crea un **volumen anónimo** (nombre hash) para cada contenedor nuevo. `down` elimina el contenedor
y el siguiente `up` crea otro contenedor con un volumen anónimo **nuevo y vacío**: los datos viejos siguen en
un volumen huérfano (por eso se acumulan en `docker volume ls`), pero nadie los vuelve a montar.

## Elemento modificado
`compose.yaml`: nombre de proyecto (`name:`), montaje en `db` y declaración del volumen `pgdata`.

## Cambio aplicado
Antes de aplicarlo se ejecutó `docker compose down`, porque `name:` cambia el nombre del proyecto
(`docker_rescue_student` → `aci606-rescue`) y los contenedores viejos quedarían fuera de su control.
```diff
diff --git a/compose.yaml b/compose.yaml
index 24e6658..6eda70c 100644
--- a/compose.yaml
+++ b/compose.yaml
@@ -1,3 +1,5 @@
+name: aci606-rescue
+
 services:
   frontend:
     build: ./frontend
@@ -20,8 +22,13 @@ services:
       POSTGRES_USER: appuser
       POSTGRES_PASSWORD: rescue123
       POSTGRES_DB: appdb
+    volumes:
+      - pgdata:/var/lib/postgresql/data
     healthcheck:
       test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
       interval: 5s
       timeout: 3s
       retries: 10
+
+volumes:
+  pgdata:
```

## Justificación
Un volumen **nombrado** tiene un ciclo de vida independiente del contenedor: `down` no lo borra y cada `up`
vuelve a montar el mismo. Fijar `name: aci606-rescue` hace que el volumen se llame siempre
`aci606-rescue_pgdata`, sin depender del nombre de la carpeta donde se clone el repositorio.

## Verificación
Archivo: `evidencias/R-08_verificacion.txt`
```

$ curl -X POST .../api/items {"name":"persistente R-08"}
{"id":1,"name":"persistente R-08","created_at":"2026-11-18T15:28:53.526363"}
$ docker compose down
$ docker compose up -d
$ curl -sS http://localhost:8080/api/items   (después de down + up)
[{"id":1,"name":"persistente R-08","created_at":"2026-11-18T15:28:53.526363"}]
$ docker inspect --format '{{json .Mounts}}' aci606-rescue-db-1
[{"Type":"volume","Name":"aci606-rescue_pgdata","Source":"/var/lib/docker/volumes/aci606-rescue_pgdata/_data","Destination":"/var/lib/postgresql/data",...}]
$ docker volume inspect aci606-rescue_pgdata
        "Name": "aci606-rescue_pgdata",
        "Labels": { "com.docker.compose.project": "aci606-rescue", "com.docker.compose.volume": "pgdata", ... }
```
Nota: el volumen nombrado arrancó vacío (inicialización nueva). El registro de prueba de R-07 estaba en un
volumen anónimo antiguo, que queda huérfano y no se borró.

**Advertencia:** `docker compose down -v` elimina también los volúmenes nombrados y, con ellos, los datos.

## Impacto si no se corrige
Toda actualización, recreación o reinicio completo del stack borra la base de datos de la aplicación.
