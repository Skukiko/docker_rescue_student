# R-07 — Nginx reenvía `/api/` a `localhost` en lugar del servicio `backend`

## Incidencia
La página carga, pero no puede comunicarse con la API: `/api/health` responde `502 Bad Gateway`.

## Síntoma
```
$ curl -sS -i http://localhost:8080/api/health | head -1
HTTP/1.1 502 Bad Gateway
```
En `frontend/index.html`, `loadItems()` lanza `throw new Error('Backend no saludable')` cuando
`/api/health` no responde 2xx, así que la página muestra **"Error: Backend no saludable"**. Esto se
deduce del código y del 502 observado; no se verificó en un navegador.

## Evidencia
Archivo: `evidencias/R-07_diagnostico.txt`
```
$ docker compose logs frontend | grep -E "upstream|connect\(\)"
frontend-1  | ... [error] 29#29: *6 connect() failed (111: Connection refused) while connecting to upstream, client: 172.18.0.1, server: _, request: "GET /api/health HTTP/1.1", upstream: "http://[::1]:8000/health", host: "localhost:8080"

$ docker compose logs frontend | grep -oE "upstream: \"[^\"]+\"" | sort | uniq -c
      4 upstream: "http://127.0.0.1:8000/health"
      4 upstream: "http://[::1]:8000/health"

$ docker compose exec frontend grep -n proxy_pass /etc/nginx/conf.d/default.conf
13:        proxy_pass http://localhost:8000/;

$ docker compose exec frontend wget -qO- http://backend:8000/health
{"status":"ok","database":"reachable"}
```
`localhost` resuelve a dos direcciones de loopback (IPv4 `127.0.0.1` e IPv6 `::1`); Nginx prueba ambas
y las dos fallan. En cambio, desde el mismo contenedor, `backend:8000` responde correctamente.

## Causa raíz
Es el mismo error conceptual de R-03, ahora en el frontend: dentro del contenedor de Nginx, `localhost`
es el propio contenedor del frontend, donde no hay nada escuchando en el puerto 8000. La API vive en el
contenedor `backend`, que se alcanza por el nombre del servicio en la red de Compose.

## Elemento modificado
`frontend/nginx.conf`: directiva `proxy_pass` de `location /api/`.

## Cambio aplicado
```diff
diff --git a/frontend/nginx.conf b/frontend/nginx.conf
index 6cb3260..82c1767 100644
--- a/frontend/nginx.conf
+++ b/frontend/nginx.conf
@@ -10,7 +10,7 @@ server {
     }
 
     location /api/ {
-        proxy_pass http://localhost:8000/;
+        proxy_pass http://backend:8000/;
         proxy_set_header Host $host;
         proxy_set_header X-Real-IP $remote_addr;
     }
```

## Justificación
Se cambia solo el host. La barra final de `http://backend:8000/` se mantiene para que Nginx quite el
prefijo `/api/` (`/api/health` → `/health`), que es como la API define sus rutas.

## Verificación

{"id":1,"name":"prueba R-07","created_at":"2026-11-18T15:27:52.374886"}

$ curl -sS http://localhost:8080/api/items
[{"id":1,"name":"prueba R-07","created_at":"2026-11-18T15:27:52.374886"}]

Flujo completo frontend → backend → PostgreSQL funcionando.

## Impacto si no se corrige
La interfaz no puede consultar ni guardar registros; la aplicación es solo una página estática.
