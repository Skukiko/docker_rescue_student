# R-06 — Puerto publicado del frontend no coincide con el puerto donde escucha Nginx

## Incidencia
El frontend figura `Up`, pero la aplicación no responde en `http://localhost:8080/`.

## Síntoma
```
$ curl -sS -v http://localhost:8080/
* Recv failure: Connection reset by peer
curl: (56) Recv failure: Connection reset by peer
```

## Evidencia
Archivo: `evidencias/R-06_diagnostico.txt`
```
$ docker compose ps frontend
docker_rescue_student-frontend-1   ...   Up 29 seconds   80/tcp, 0.0.0.0:8080->8080/tcp, [::]:8080->8080/tcp

$ docker compose exec frontend netstat -tln
tcp        0      0 127.0.0.11:44007        0.0.0.0:*               LISTEN
tcp        0      0 0.0.0.0:80              0.0.0.0:*               LISTEN

$ docker compose exec frontend wget -qO- http://127.0.0.1:80/ | head -6
<!doctype html>
...
  <title>ACI606 Docker Rescue</title>

$ docker compose exec frontend wget -qO- http://127.0.0.1:8080/
wget: can't connect to remote host (127.0.0.1): Connection refused
```
(`127.0.0.11:44007` es el resolver DNS embebido de Docker, no Nginx).

## Causa raíz
`ports: "8080:8080"` reenvía el puerto 8080 del host al puerto **8080 del contenedor**, pero
`nginx.conf` tiene `listen 80;` y el Dockerfile declara `EXPOSE 80`. En el 8080 del contenedor no
escucha nada, así que el proxy de Docker acepta la conexión del host y luego la cierra (reset).

## Elemento modificado
`compose.yaml`: servicio `frontend`, `ports`.

## Cambio aplicado
```diff
diff --git a/compose.yaml b/compose.yaml
index a6d8b74..24e6658 100644
--- a/compose.yaml
+++ b/compose.yaml
@@ -2,7 +2,7 @@ services:
   frontend:
     build: ./frontend
     ports:
-      - "8080:8080"
+      - "8080:80"
     depends_on:
       - backend
```

## Justificación
El formato es `HOST:CONTENEDOR`. Se mantiene el puerto 8080 en el host (el que se usa para acceder) y se
apunta al 80 donde escucha Nginx, sin tocar la configuración de Nginx ni la imagen.

## Verificación
Archivo: `evidencias/R-06_verificacion.txt`
```
$ docker compose ps frontend
docker_rescue_student-frontend-1   ...   Up 3 seconds   0.0.0.0:8080->80/tcp, [::]:8080->80/tcp
$ curl -sS -o /dev/null -w "HTTP %{http_code}\n" http://localhost:8080/
HTTP 200
$ curl -sS http://localhost:8080/ | grep title
  <title>ACI606 Docker Rescue</title>
$ curl -sS -i http://localhost:8080/api/health | head -1
HTTP/1.1 502 Bad Gateway
```
La página estática ya se sirve. El `502` de `/api/` es una falla distinta del proxy, tratada en **R-07**.

## Impacto si no se corrige
Ningún usuario puede acceder a la aplicación desde fuera de Docker, aunque todos los contenedores parezcan estar en ejecución.
