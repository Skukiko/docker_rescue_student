# M-04 — Documentación reproducible, diagramas de arquitectura y devcontainer

## Incidencia
Mejora de reproducibilidad. El README recibido solo indicaba `docker compose up --build -d` y advertía que
el sistema tenía fallas; no explicaba configuración, verificación, persistencia ni diagnóstico.

## Síntoma
Una persona nueva no tenía forma de saber qué variables existen, cómo comprobar que todo funciona, que `down -v`
borra los datos, ni cómo diagnosticar un 502 o un 503.

## Evidencia
`bitacora/original/README.md`: solo contiene "Arquitectura general", "Situación inicial" e "Inicio sugerido"
(`docker compose up --build -d`, `ps`, `logs`). No existían `docs/` ni `.devcontainer/`.

## Causa raíz
Documentación operativa ausente.

## Elemento modificado
`README.md` (reescrito; el original queda en `bitacora/original/README.md` y se enlaza), `docs/arquitectura.md` (nuevo) y
`.devcontainer/devcontainer.json` (nuevo).

## Cambio aplicado
- **README.md:** requisitos; configuración con tabla de variables (y la advertencia de que `POSTGRES_*` solo se aplican a un volumen vacío);
  construir e iniciar; verificar con `curl` y `psql`; detener; recrear comprobando persistencia; **advertencia sobre
  `docker compose down -v`**; tabla de diagnóstico por síntoma; estructura del repositorio.
- **docs/arquitectura.md:** diagrama mermaid del estado **inicial** (fallas R-01…R-08 marcadas), del estado **final**,
  diagrama de secuencia del arranque y la recuperación, y una tabla de decisiones.
- **.devcontainer/devcontainer.json:** imagen `mcr.microsoft.com/devcontainers/universal:2`, `forwardPorts: [8080]`.

Diff: `git show` de este commit (son archivos de documentación; el diff completo es el contenido de los archivos).

## Justificación
El criterio de éxito de la evaluación es que la solución sea **reproducible**. El README permite levantar, verificar
y diagnosticar sin conocer el historial. El devcontainer garantiza un entorno con Docker en Codespaces y reenvía el puerto del frontend.

## Verificación
Archivo: `evidencias/M-04_verificacion.txt`. Los comandos de la sección 4 del README se ejecutaron tal como están escritos:

## Impacto si no se corrige
La solución depende del conocimiento de quien la reparó; hay riesgo de pérdida de datos por un `down -v` sin advertencia.
