# M-02 — Healthchecks, reinicio automático, red explícita y logs sin buffer

## Incidencia
Mejora de operación. Solo db tenía healthcheck; backend y frontend podían figurar `Up` sin funcionar
(R-06 y R-07 son ejemplos). Ningún servicio tenía política de reinicio (R-05: `Policy=no`).

## Síntoma
"Up" no significa "sano": no había forma de que Compose ni el operador detectaran un backend sin base de datos o un Nginx que no responde.

## Evidencia
Archivo: `evidencias/M-02_diagnostico.txt` (antes del cambio):
```
$ docker compose ps
aci606-rescue-backend-1    ...   Up 53 seconds                 8000/tcp
aci606-rescue-db-1         ...   Up About a minute (healthy)   5432/tcp
aci606-rescue-frontend-1   ...   Up 40 seconds                 0.0.0.0:8080->80/tcp
Health=sin-healthcheck Restart=no Networks=aci606-rescue_default     (backend)
Health=sin-healthcheck Restart=no Networks=aci606-rescue_default     (frontend)
Health=healthy         Restart=no Networks=aci606-rescue_default     (db)
$ docker compose exec backend which curl
exit=1
```
`python:3.12-slim` no incluye `curl`, así que el healthcheck del backend se hace con Python (stdlib).

## Causa raíz
Falta de chequeos de salud de aplicación, de política de reinicio y de una red declarada explícitamente.

## Elemento modificado
`compose.yaml` (los 3 servicios) y `backend/Dockerfile`.

## Cambio aplicado
Diff completo en `evidencias/M-02_diff.txt`:
```diff
--- a/backend/Dockerfile
+++ b/backend/Dockerfile
 FROM python:3.12-slim
 WORKDIR /app
+ENV PYTHONDONTWRITEBYTECODE=1 \
+    PYTHONUNBUFFERED=1
--- a/compose.yaml
+++ b/compose.yaml
   frontend:
     depends_on:
-      - backend
+      backend:
+        condition: service_healthy
+    healthcheck:
+      test: ["CMD", "wget", "-q", "-O", "/dev/null", "http://127.0.0.1/"]
+      interval: 10s
+      timeout: 3s
+      retries: 3
+    restart: unless-stopped
+    networks:
+      - app_net
   backend:
+    healthcheck:
+      test: ["CMD", "python", "-c", "import urllib.request,sys; sys.exit(0 if urllib.request.urlopen('http://127.0.0.1:8000/health', timeout=3).status == 200 else 1)"]
+      interval: 10s
+      timeout: 5s
+      retries: 5
+      start_period: 10s
+    restart: unless-stopped
+    networks:
+      - app_net
   db:
+    restart: unless-stopped
+    networks:
+      - app_net
+
+networks:
+  app_net:
```

## Justificación
- **Backend:** el healthcheck llama a `/health`, que hace `SELECT 1`, así que mide la API y su base de datos. Si `/health` responde 503 o no responde, `urlopen` lanza una excepción y el proceso sale distinto de 0.
- **Frontend:** `wget` viene en `nginx:alpine` (BusyBox). Con `depends_on: service_healthy`, Nginx arranca solo cuando el backend responde de verdad.
- **`restart: unless-stopped`:** recupera los servicios tras una caída o un reinicio del daemon, pero respeta un `docker compose stop` manual.
- **`app_net`:** documenta la topología en el propio archivo y deja lugar para segmentar redes más adelante.
- **`PYTHONUNBUFFERED=1`:** los logs salen al instante por `docker compose logs`. **`PYTHONDONTWRITEBYTECODE=1`:** no se generan `.pyc` dentro del contenedor.

Observación: en la primera lectura el frontend aparecía `health: starting`, porque su primer chequeo
ocurre a los 10 s (`interval`); 12 s después figuraba `healthy`. La red anterior `aci606-rescue_default` quedó
huérfana (sin contenedores) porque el compose ya no la declara; se puede borrar con `docker network rm aci606-rescue_default`.

## Impacto si no se corrige
Fallas silenciosas (contenedores "Up" que no atienden), orden de arranque frágil y servicios que no se recuperan solos.
