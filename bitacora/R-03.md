# R-03 — `DATABASE_URL` apunta a `localhost` en lugar del servicio `db`

## Incidencia
Tras R-02, el backend falla en el evento `startup` al conectarse a PostgreSQL y termina con `Exited (3)`.

## Síntoma
`Application startup failed. Exiting.` después de un `Connection refused`.

## Evidencia
Archivo: `evidencias/R-03_diagnostico.txt`
```
$ docker compose logs backend | grep -A1 "connection to server"
backend-1  | psycopg2.OperationalError: connection to server at "localhost" (::1), port 5432 failed: Connection refused
backend-1  | connection to server at "localhost" (127.0.0.1), port 5432 failed: Connection refused

$ docker compose config | grep DATABASE_URL
      DATABASE_URL: postgresql://appuser:wrongpass@localhost:5432/appdb

$ docker compose run --rm --entrypoint python backend -c "import socket; ..."
db -> 172.18.0.2
localhost -> 127.0.0.1

$ docker network inspect docker_rescue_student_default --format "{{range .Containers}}..."
docker_rescue_student-db-1 172.18.0.2/16
docker_rescue_student-frontend-1 172.18.0.4/16
```
(El backend no aparece en la red porque estaba detenido: un contenedor detenido no tiene endpoint.)

## Causa raíz
Cada contenedor tiene su propio namespace de red. Dentro del backend, `localhost` es el propio
contenedor del backend, donde no hay ningún PostgreSQL escuchando. La base de datos está en otro contenedor,
que el DNS interno de Docker resuelve con el nombre del servicio `db` (172.18.0.2) dentro de la red del proyecto.

## Elemento modificado
`compose.yaml`: servicio `backend`, variable `DATABASE_URL`.

## Cambio aplicado
```diff
diff --git a/compose.yaml b/compose.yaml
index 63ab039..c06c456 100644
--- a/compose.yaml
+++ b/compose.yaml
@@ -9,7 +9,7 @@ services:
   backend:
     build: ./backend
     environment:
-      DATABASE_URL: "postgresql://appuser:wrongpass@localhost:5432/appdb"
+      DATABASE_URL: "postgresql://appuser:wrongpass@db:5432/appdb"
     depends_on:
       - db
```

## Justificación
Se usa el nombre del servicio, que es estable aunque cambie la IP del contenedor. La contraseña
incorrecta (`wrongpass`) se deja a propósito para corregirla aparte en R-04 (una falla, un cambio).

## Verificación
Archivo: `evidencias/R-03_verificacion.txt`
```
$ docker compose config | grep DATABASE_URL
      DATABASE_URL: postgresql://appuser:wrongpass@db:5432/appdb
$ docker compose logs backend | tail -8
backend-1  | sqlalchemy.exc.OperationalError: (psycopg2.OperationalError) connection to server at "db" (172.18.0.2), port 5432 failed: FATAL:  password authentication failed for user "appuser"
```
La conexión TCP a `db:5432` ya se establece: PostgreSQL contesta y rechaza la autenticación.
Esa es una falla distinta, tratada en **R-04**.

## Impacto si no se corrige
El backend nunca alcanza la base de datos; la API no arranca.
