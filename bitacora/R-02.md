# R-02 — Falta el driver de PostgreSQL (`psycopg2`)

## Incidencia
Tras corregir R-01, el backend vuelve a terminar con `Exited (1)` durante la importación de `main.py`.

## Síntoma
El contenedor `backend` no queda en ejecución; el traceback ocurre al crear el engine de SQLAlchemy.

## Evidencia
Archivo: `evidencias/R-02_diagnostico.txt`
```
$ docker compose logs backend | tail -3
backend-1  |   File "/usr/local/lib/python3.12/site-packages/sqlalchemy/dialects/postgresql/psycopg2.py", line 690, in import_dbapi
backend-1  |     import psycopg2
backend-1  | ModuleNotFoundError: No module named 'psycopg2'

$ docker compose run --rm --entrypoint pip backend list | grep -i -E "sqlalchemy|psycopg"
SQLAlchemy        2.0.36

$ cat backend/requirements.txt
fastapi==0.115.5
uvicorn[standard]==0.32.1
SQLAlchemy==2.0.36
```

## Causa raíz
Una URL `postgresql://...` hace que SQLAlchemy use por defecto el dialecto `postgresql+psycopg2`, que
necesita el paquete `psycopg2`. SQLAlchemy no lo instala como dependencia y `requirements.txt` no lo declara.

## Elemento modificado
`backend/requirements.txt`.

## Cambio aplicado
```diff
diff --git a/backend/requirements.txt b/backend/requirements.txt
index 0fe9b36..2178c3b 100644
--- a/backend/requirements.txt
+++ b/backend/requirements.txt
@@ -1,3 +1,4 @@
 fastapi==0.115.5
 uvicorn[standard]==0.32.1
 SQLAlchemy==2.0.36
+psycopg2-binary==2.9.10
```

## Justificación
`psycopg2-binary` trae wheels precompiladas que incluyen libpq, así que no hace falta instalar `gcc`
ni `libpq-dev` en `python:3.12-slim`. La versión queda fijada, igual que las demás dependencias, para que el build sea reproducible.

## Verificación
Archivo: `evidencias/R-02_verificacion.txt`
```
$ docker compose run --rm --entrypoint pip backend list | grep -i -E "sqlalchemy|psycopg"
psycopg2-binary   2.9.10
SQLAlchemy        2.0.36
$ docker compose logs backend | tail -6
backend-1  | connection to server at "localhost" (127.0.0.1), port 5432 failed: Connection refused
...
backend-1  | ERROR:    Application startup failed. Exiting.
```
El `ModuleNotFoundError` desaparece. El backend ya intenta conectarse a PostgreSQL y falla por
otra causa (host `localhost`), tratada en **R-03**. El código de salida cambia de `1` a `3`, el que uvicorn
usa cuando falla el evento `startup`.

## Impacto si no se corrige
La API no puede crear el engine de base de datos y nunca arranca.
