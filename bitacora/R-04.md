# R-04 — Contraseña de `DATABASE_URL` distinta de `POSTGRES_PASSWORD`

## Incidencia
Con el host ya corregido (R-03), PostgreSQL rechaza la autenticación del backend, que termina con `Exited (3)`.

## Síntoma
`FATAL: password authentication failed for user "appuser"`, que aparece tanto en el cliente (backend) como en el servidor (db).

## Evidencia
Archivo: `evidencias/R-04_diagnostico.txt`
```
$ docker compose logs backend | grep FATAL
backend-1  | sqlalchemy.exc.OperationalError: (psycopg2.OperationalError) connection to server at "db" (172.18.0.2), port 5432 failed: FATAL:  password authentication failed for user "appuser"

$ docker compose logs db | grep -E "FATAL|DETAIL"
db-1  | 2026-11-18 15:25:05.406 UTC [63] FATAL:  password authentication failed for user "appuser"
db-1  | 2026-11-18 15:25:05.406 UTC [63] DETAIL:  Connection matched file "/var/lib/postgresql/data/pg_hba.conf" line 128: "host all all all scram-sha-256"

$ docker compose config | grep -E "DATABASE_URL|POSTGRES_PASSWORD"
      DATABASE_URL: postgresql://appuser:wrongpass@db:5432/appdb
      POSTGRES_PASSWORD: rescue123
```

## Causa raíz
La imagen `postgres` crea el usuario `appuser` con la contraseña de `POSTGRES_PASSWORD` (`rescue123`).
El backend se autentica con `wrongpass`. Las conexiones TCP se validan con `scram-sha-256` según `pg_hba.conf`
(línea 128), así que la contraseña debe coincidir.

## Elemento modificado
`compose.yaml`: servicio `backend`, variable `DATABASE_URL` (credencial).

## Cambio aplicado
```diff
diff --git a/compose.yaml b/compose.yaml
index c06c456..3fa7de9 100644
--- a/compose.yaml
+++ b/compose.yaml
@@ -9,7 +9,7 @@ services:
   backend:
     build: ./backend
     environment:
-      DATABASE_URL: "postgresql://appuser:wrongpass@db:5432/appdb"
+      DATABASE_URL: "postgresql://appuser:rescue123@db:5432/appdb"
     depends_on:
       - db
```

## Justificación
Se ajusta el cliente al servidor y no al revés. Cambiar `POSTGRES_PASSWORD` no tendría efecto sobre
un directorio de datos ya inicializado, porque la imagen solo lo aplica en la primera inicialización. La duplicación de la
credencial se elimina más adelante en M-01 (variables compartidas).

## Impacto si no se corrige
El backend no puede autenticarse: la API no arranca y no se crea la tabla `items`.
